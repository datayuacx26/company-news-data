# Launching Slack Insights for AI Agents

If you care about minimizing churn, you need to find issues before your users do.


We just launched insights for your agents in Slack.


You should not have to leave Slack to discover your agent is breaking in production.


The signal should reach the place where the team already decides what to do next.


## What comes to Slack


You get a configurable report delivered directly into Slack. It can run daily, weekly, or on the cadence that matches how your team reviews the agent.


Each report can show:


- Where users were stuck, confused, or frustrated
- Where agents silently failed
- What patterns are emerging across conversations
- Which accounts, tools, workflows, or cost spikes need attention
- Which examples someone should inspect


The report can focus on the signals your team actually reviews: failures, topics, cost, latency, usage quotas, account behavior, or a specific workflow you want to watch after a release.


## Make the review automatic


The point of a recap is to remove the part where someone has to remember to go look.


If a tool starts looping, it should show up. If an account keeps asking for the same unsupported workflow, it should show up. If cost moves suddenly, it should show up. If users are getting frustrated after a release, it should show up before the next customer call.


That is why Slack matters. It turns agent monitoring into a review habit instead of a dashboard someone opens when there is already a problem.


## Why the evidence matters


Summaries are only useful when the team can inspect the evidence behind them.


If the recap says users were frustrated, the sessions should be there. If it says a topic is growing, the examples should be there. If it says an agent silently failed, the trace should be there. If it says cost moved, the runs, models, tools, and workflows behind the movement should be there too.


The summary starts the conversation. The evidence lets the team act on it.


## What we have seen in beta


We have been running recap betas with customers, and the clearest signal is simple: recaps matter when they change what the team does next.


Customers have already used them to quickly find and stop sudden AI cost increases of $2K+ per day. They have used them to notice recurring user confusion, inspect production examples, and decide which issues needed immediate work.


That is the reason we care about Slack as a product surface.


The dashboard is where teams dig in. Slack is where the signal becomes part of the operating rhythm.


The workflow should be simple:


1. Watch real user behavior.
2. Surface the few changes that matter.
3. Keep the examples attached.
4. Route the issue to the right owner.
5. Check whether the same behavior improves later.


That is how agents get better after launch.
