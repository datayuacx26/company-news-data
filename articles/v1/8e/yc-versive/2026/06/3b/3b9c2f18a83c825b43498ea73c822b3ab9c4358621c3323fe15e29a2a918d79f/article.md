# Website testing, now inside the interview

[Back to updates](https://www.getversive.com/blog)


June 26, 2026 •


Product Updates


### Website testing, now inside the interview


Website tests now run in an embedded browser inside Versive, with per-participant journeys and page-level insights. Plus: attach a live website to any question.


---


Testing a live website used to mean sending participants to a new tab, and losing sight of them the moment they left. Now the website comes to the interview instead.


### An embedded browser for website tests


Website test questions now open the site in a **virtual browser embedded right inside the interview** . Participants browse the real, live website while staying in Versive the whole time: no tab switching, no lost context, and the AI interviewer can keep the conversation going alongside the task.


### See exactly where participants went


Because the browsing happens inside Versive, you get much richer results:


- **Per-participant journeys** : see the pages each participant visited, in order, with time spent on each page.
- **Most-visited pages** : insights now aggregate across participants to show which pages drew the most attention and how long people spent on them on average.


Pair the journey data with what participants said in the interview, and you can connect *what they did* with *why they did it* in a single study.


### Put a live website next to any question


Website tests aren't the only place this is useful. You can now attach a **live website alongside any question type** , whether it's an open-ended question, a rating, or a multiple choice, so participants can browse while they answer.


Ask participants to explore your pricing page and rate its clarity, or browse a competitor's site and describe their first impression. If consecutive questions use the same website, the browsing session carries over, so participants pick up right where they left off.
