## Target your study to only active participants


If your study setup typically uses participant groups or saved filter sets, some of the participants who matched last time may be less active today. Until now, there hasn’t been a way to filter for activity directly.


The new ‘Active in the last X days’ filter does this for you. Narrow down the last time a participant was active in the platform, which includes logging in, viewing their dashboard or taking a study. Add it to your study’s filters, combine it with an existing participant group, or save it as part of an existing filter set so your study reaches people those who are genuinely active on the platform.


This means that you can reuse participant groups or saved filter sets without the need to prune or rebuild manually, as less active participants simply won’t be included.


Explore[in platform](https://app.prolific.com/) or via[API](https://docs.prolific.com/api-reference/filters/filters-overview)

## Configure your task layout in AI Task Builder, with more flexibility to come


Where your stimulus sits, which questions appear alongside it and how the screen is split are critical layout decisions that shape how well participants can complete a task. Instead of a fixed structure,[AI Task Builder](https://www.prolific.com/ai-task-builder) now lets you define the layout for your task.


Each page is built from rows, and each row can hold up to two columns. Put your stimulus in one column and your questions in the next for a clean side-by-side layout, or stack a dataset field above supporting context for something more guided. Each column can hold:


- A dataset field (image, text, audio, etc.)
- An[instruction](https://docs.prolific.com/api-reference/ai-task-builder/instructions) (radio buttons, free text, text with unit selection, file uploads)
- A content block for supporting copy


Mix and match to build side-by-side comparisons, structured annotation tasks, and more.


Unsure how to get started? Explore the new functionality with these ready-made GitHub repos:


- [Prolific Smart Glasses POV Video Collection](https://github.com/prolific-oss/prolific-smart-glasses-pov-video-collection)
- [AI-Task-Builder-Image-Collection](https://github.com/prolific-oss/AI-Task-Builder-Image-Collection)
- [AI-Task-Builder-Free-Text-Collection](https://github.com/prolific-oss/AI-Task-Builder-Free-Text-Collection)


This is the first step in a series of flexibility improvements in AI Task Builder, watch this space for more! Available now via[API](https://docs.prolific.com/api-reference/ai-task-builder/configurable-layout) for AI Task Builder[Batches](https://docs.prolific.com/api-reference/ai-task-builder/batches) (annotation tasks).

## Use AND / OR logic in saved filter sets


When you need to target a complex audience, AND / OR logic lets you define multiple conditions.


Now, you can apply the same logic to a Filter Set and within nested groups, for more precise targeting (e.g. Employed = full-time **OR** part-time **AND** Age = 18-25). This saves you time from manually applying filters each time, especially useful if you run multiple studies with the same criteria.


Try it now in the[UI](https://app.prolific.com/) and the[API](https://docs.prolific.com/api-reference/filters/advanced-filtering) .


## Quality of life updates this month


- **Fetch cleaner message results via the API.** If your integration sends automated messages to participants (like return requests or warnings), you can now exclude those from your results when polling` GET /api/v1/messages/` . Use the new` excluded_sender_ids` parameter to pass a comma-separated list of user IDs, so you only get back genuine participant replies.[Find your sender ID](https://docs.prolific.com/api-reference/users/get-user) , then[get started with filtering your messages](https://docs.prolific.com/api-reference/messages/get-messages) .
- **Search all filters from any tab.** Search is now available on all tabs (Premium, Popular, All) and searches the entire catalogue at once, not just the tab you’re viewing.
- **Streamlining our terminology** . “Screener” and “Prescreener” are now called “Filter” in the UI, to align with the language in the API. This means that across the UI and API:


- Filters: the criteria you use to target participants for a study (e.g. age)
- Screeners: a custom screener study you launch to qualify participants before you invite them to your main study
