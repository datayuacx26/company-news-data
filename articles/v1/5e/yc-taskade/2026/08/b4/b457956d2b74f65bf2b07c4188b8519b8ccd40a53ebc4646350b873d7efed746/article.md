## Why This Category Confusion Exists


"AI app builder" got coined in 2023 for tools that wrote frontend code from a prompt, and the label was accurate then. Three shifts since made it a bad label for buying decisions.


1. **The generation problem got solved before the operating problem did.** Producing a clean React screen from a sentence is now table stakes across half a dozen tools. Keeping that screen connected to real records, real logins, and real reminders six months later is still where projects die.
2. **Operators started buying software directly.** The shop owner, the transaction coordinator, and the agency lead now evaluate tools without an engineer in the room. A GitHub export reads as a deliverable to a developer and as a dead end to them.
3. **Runtime platforms started generating too.** Once a workspace could generate its own database, agents, and portals from a prompt, the same "one prompt, one app" language covered both categories and stopped distinguishing them.


The result is a shopping list where a browser code sandbox and a hosted ops runtime look identical on a feature grid. The architecture difference is what you actually buy. ## Who Should Stay on a Code Builder


This is the section most vendor comparisons skip. Stay in code when the constraint you refuse to drop is one a runtime cannot honor.


- **Source code is the deliverable.** Client contracts, acquisitions, and some audits require a repo you hand over. A runtime is the wrong answer, full stop.
- **You are building a product, not running an operation.** Vertical SaaS you intend to sell needs custom UI, its own billing, and its own roadmap.
- **Pixel-level design control is the differentiator.** Marketing surfaces and consumer apps live and die on layout nuance.
- **You already employ the people who host things.** If DevOps is salaried and idle, hosting is close to free for you and the calculus flips.
- **Your stack has hard environment requirements.** Specific regions, private networking, or a compliance regime your security team already certified.


Constraint you refuse to drop Lean this way


Handing a client the source repo Lovable or in-house engineering


Fastest UI exploration in a browser Bolt.new


Polished components into an existing app Vercel v0


Internal tools on an existing SQL warehouse Retool


Portals on data already in Airtable Softr


Live ops system with agents and portals Taskade Genesis


Lovable, Bolt.new, v0, Retool, and Softr are not weak products. They are precise ones. The failure mode is buying a precise product for a problem shaped differently, which is what happens when both categories share a label.

## What Taskade Genesis Owns vs What You Pair


Honest boundaries beat feature checklists.


**Strong fit:** job and work-order boards, CRM records, invoicing and AR chase, client and parent portals, intake forms, approval routing, agents grounded on your Projects, 100+ bidirectional integrations.


**Honest gaps:**


- **No GPS or fleet telematics.** Keep your existing provider and reference job status on the board.
- **No MLS or IDX listing feed.** Real estate ops work; listing syndication does not come included.

If any pitch tells you a runtime replaces custom source ownership, walk away from it no matter who is making it, including us.

## Can I Export the Code?


Not as React source, and that distinction matters. Taskade Genesis pushes a portable app bundle to GitHub, which round-trips Projects, agents, automations, and theme into another workspace. What it does not hand you is a component tree you refactor in your own build pipeline. Code builders optimize export; Taskade Genesis optimizes the system that answers your phone on Monday. Decide which of the two you actually need before you start.

## Questions to Ask Vendors (Both Categories)


- Who maintains auth for client logins, and who gets paged when it breaks?
- Where do automations run, and can I see the log?
- Can the owner change a field without an engineer?
- What happens to the app if we stop paying?
- What is included in the bill, and what arrives as a second invoice?


Taskade Genesis answers favor operator control. Code builders answer favor export and hosting control. Write the answers down before the demos blur together.


## Three Mistakes That Cost Operators the Most


- **Buying a runtime when a contract mandates source code.** Know the constraint before the demo.
- **Ignoring client auth.** A pretty dashboard with no[App Users](https://www.taskade.com/wiki/genesis/app-users) still generates status phone calls.
- **Assuming GPS or IDX comes included.** Neither path ships fleet tracking or listing feeds on its own. Taskade Genesis is strongest on the office side, and both paths need a real integration beyond that.

3. Is source ownership a contractual or compliance requirement?

## FAQ


Is Taskade Genesis an AI app builder?


It builds apps, and what you get is a running ops runtime rather than a code archive. Compare what each category is for, not the shared marketing label.[Living software](https://www.taskade.com/wiki/genesis/living-software) is the closer description.


Can Taskade Genesis and Lovable coexist?


Yes. Prototype UI in Lovable and run operations in Taskade Genesis until your needs converge on one. Set a date for that convergence so the prototype does not quietly become production.


Where do I start with Taskade Genesis?


[/create](https://www.taskade.com/create) , or a targeted generator such as[field service ops dashboard](https://www.taskade.com/generate/dashboards/field-service-ops-dashboard) . The[first app walkthrough](https://www.taskade.com/learn/genesis/first-app) covers the first hour.


What does the Taskade Genesis path cost?


Free to start. Every new account gets a one-time 6,000 credit grant, 1,000 at signup plus 5,000 with your first build, which covers one complete app end to end. From there, Pro is $10 per month billed annually ($20 month to month) and Business is $25 per month billed annually ($50 month to month). There is no separate hosting or deploy bill stacked on top of the plan.


Do I get a database, or do I bring one?


You get one. Projects are the database, with 7 views over the same records including Board, Table, Calendar, and Gantt. On a code path you provision and model the database yourself. See[database projects](https://www.taskade.com/wiki/genesis/database-projects) .


How do client logins work without building auth?


App Users are native. You publish the app, invite the people who need a login, and scope what they see. Permissions run 7 levels from Owner down to Viewer. Details in[App Users](https://www.taskade.com/learn/genesis/app-users) and[roles and permissions](https://www.taskade.com/learn/account/roles-permissions) .


Can I connect the tools we already use?


Yes, through 100+ bidirectional integrations, where triggers pull events in and actions push data out. The hosted MCP server is available on every paid plan for AI tools that need to reach your workspace. Taskade Genesis does not act as an outbound MCP client against arbitrary external servers.


What if my requirement really is a React repo?


Then use Lovable, Bolt.new, or in-house engineering, and do not let a runtime comparison talk you out of it. That is a legitimate requirement, and a managed runtime is the wrong tool for it.


Which path is cheaper for a five-person shop?


Usually Taskade Genesis, because the code path's dominant cost is engineer hours rather than subscription. Run both numbers with hosting, auth build, and 24 months of field changes included before you decide.
