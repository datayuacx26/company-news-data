[Micah Bhakti, Director of Product Management](https://www.singlestore.com/blog/author/micah-bhakti/)


Organizations today are making a fundamental shift in how they think about data. Instead of locking information inside proprietary systems, enterprises are increasingly standardizing on open data formats that provide flexibility, interoperability, and long-term ownership of their data assets.


At SingleStore, we believe open data is the foundation for the next generation of agentic applications. That's why we're announcing our third generation Cluster architecture, running on zero-copy data fabric with direct support for Apache Iceberg.


Together, these innovations enable organizations to build and deploy Agentic Applications using SingleStore’s HTAP engine, without duplicating Open Data across workloads or applications.


## The Rise of Open Data


Data is the fuel for modern intelligent applications and AI, but too often organizations face a difficult tradeoff: either move data into specialized systems to gain performance and generate insights, or leave data in open storage and sacrifice operational capabilities.


Apache Iceberg has emerged as the leading open table format because it solves many of the challenges of managing large-scale data lakes. Organizations gain a standardized, open way to store and govern data while maintaining freedom of choice across tools and platforms.


Agentic applications need more than readable data. Agents have to discover information, run transactions, generate insights, and keep pace with data as it changes — which means the underlying platform needs to actively participate, not just serve files. Reading isn't enough; the platform has to read, write, and reason.


## HTAP Engine for Agentic Apps


SingleStore's unique HTAP (Hybrid Transactional and Analytical Processing) architecture enables organizations to unify operational workloads, analytics, and AI on a single engine.


With SingleStore, applications and AI agents can:


-


Read data from open Iceberg tables


-


Write updates and operational changes


-


Perform real-time analytics


-


Execute vector search and retrieval


-


Combine structured and unstructured data


-


Generate insights and automate workflows using agentic workflows


This ability to read, write, and reason on data makes SingleStore the ideal engine for agentic applications.


Rather than moving data between transactional systems, warehouses, lakes, and AI infrastructure, organizations can build intelligent applications directly where data lives.


## Third Generation Clusters using Zero-Copy Data Fabric


Today SingleStore is introducing its third generation cluster architecture, designed to deliver extreme scalability and isolation while sharing data across hundreds or thousands of applications.


SingleStore’s Zero-Copy data fabric enables compute clusters to attach any database without copying, duplicating, or relocating data. This reduces organizational complexity, and removes the challenge of managing disparate silos of data between operational and analytic database engines.


Organizations can create clusters, scale workloads, and deploy AI-powered applications directly against their data while maintaining a single source of truth. The best part is this is an automatic upgrade for existing customers, and no migration is needed to move from legacy compute “workspaces” to third generation clusters.


The result is faster time to insight, lower costs, and dramatically simplified data operations.


## Smart Read Replicas


Agentic workloads often compete with operational systems for resources, creating bottlenecks and unpredictable performance. Smart Read Replicas let teams attach dedicated clusters to a production database without copying the underlying data, so applications, AI inference, and analytics can scale independently while still reading from the same governed, up-to-date source.


## Database Branching


Just as software teams branch code, data should work the same way. Database Branching lets teams spin up full database environments in seconds without duplicating the underlying data, so developers can test features, data engineers can validate pipeline changes, and AI teams can experiment with models and prompts — all against real production data, and without the traditional costs of duplication.


## Smart DR


Traditional disaster recovery means paying for replicated infrastructure that sits idle most of the time. Smart DR uses the same Zero-Copy data fabric to let organizations deploy hot or cold clusters across cloud regions — cutting recovery time and operational complexity while optimizing total cost.


## Open Data Meets Open Intelligence


Apache Iceberg solves the problem of where data lives and who can access it. SingleStore solves what you can do with it: transacting, analyzing, searching, and reasoning in real-time, without moving data to yet another system. Together, they close the gap between open data and intelligent applications.


The architecture described here — Gen3 HTAP clusters, Zero-Copy data fabric, read replicas, branching, smart disaster recovery — isn't just an operational convenience. It's what makes agentic applications practical at enterprise scale.
