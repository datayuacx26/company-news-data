# Claude Code Memory: Give Your Agent Persistent Context Across Sessions

## Layer 1: CLAUDE.md


CLAUDE.md is a plain markdown file. Claude reads it at the start of every session and treats it as persistent context.


You write it. You control what goes in.


**Four scopes, loaded from broadest to most specific:**


Scope Location Use case


**Managed policy**` /Library/Application Support/ClaudeCode/CLAUDE.md` (macOS) or` /etc/claude-code/CLAUDE.md` (Linux) Org-wide rules, MDM-deployed


**User**` ~/.claude/CLAUDE.md` Personal preferences, all projects


**Project**` ./CLAUDE.md` or` ./.claude/CLAUDE.md` Team-shared rules, version-controlled


**Local**` ./CLAUDE.local.md` Personal project notes, gitignored


For most developers, two files matter:` ~/.claude/CLAUDE.md` for personal preferences and` ./CLAUDE.md` for project rules. Commit the project file to version control — your entire team gets the same context when they clone the repo.


**Keep CLAUDE.md under 200 lines.** Longer files reduce how consistently Claude follows the instructions. More lines means less attention per line. Use` .claude/rules/` for path-specific rules in large codebases (covered in Layer 3).


**Generating a starter file:**


Run` /init` inside any Claude Code session. It analyzes your codebase and generates a starting CLAUDE.md automatically. Edit from there — do not write from scratch.


*Practical walkthrough: writing a CLAUDE.md that actually changes Claude's behavior in sessions*


**What a working CLAUDE.md looks like:**


```text
# Project: Invoice Tracker


## Build & Test Commands
-   Start dev:   `pnpm dev`   (NOT npm — this project uses pnpm)
-   Test:   `pnpm test`
-   Lint:   `pnpm lint && pnpm type-check`
-   Build:   `pnpm build`


## Stack & Architecture
-   Next.js 16 App Router + TypeScript
-   Database: Postgres via Prisma — migrations in   `prisma/migrations/`
-   Auth: Clerk (not NextAuth — we migrated in Q1 2026)
-   Payments: Stripe Payment Element (not Checkout)
-   Styling: Tailwind + shadcn/ui components in   `src/components/ui/`


## Key Conventions
-   Named exports only — no default exports
-   2-space indentation throughout
-   API route handlers go in   `src/app/api/`   — keep under 50 lines
-   Server components by default; add "use client" only when needed


## Known Issues (Do NOT "Fix")
-   TypeScript error in   `src/lib/legacy-stripe.ts`   — suppressed with @ts-ignore
Reason: Stripe types not yet updated for Payment Element v2


## Do NOT Do
-   Never run   `npm`   — always use   `pnpm`
-   Never push directly to   `main`   — always create a PR
-   Never modify files in   `src/generated/`   — they are auto-overwritten
```


Notice the "Do NOT Do" and "Known Issues" sections. These are where CLAUDE.md earns its keep.


Every project has a` src/generated/` directory that Claude keeps trying to modify. Every codebase has an auth library that Claude thinks should be swapped for a newer one. Write them down once — stop correcting them every session.


## Layer 2: Auto Memory (MEMORY.md)


Auto memory is the inverse of CLAUDE.md. You write instructions; Claude writes its own learnings.


Requires Claude Code v2.1.59 or later — check with` claude --version` .


**How Claude decides what to save:**


Claude writes to auto memory when it detects something that is recurrent, not inferrable from the codebase, stable, and project-specific. A package manager preference gets saved. A one-off debug step does not.


**Where auto memory lives:**


` ~/.claude/<project>/memory/MEMORY.md` — machine-local, not synced across machines or cloud environments.


**What it actually contains:**


```text
# MEMORY.md (auto-generated by Claude Code)
Last updated: 2026-05-28


## Build System
-   Project uses pnpm v9, not npm. Use   `pnpm`   for all commands.
-   Integration tests require a local Redis instance on port 6379.
-   `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`   must be set in .env.local to run auth.


## Discovered Patterns
-   Custom hooks in   `src/hooks/`   follow the   `use[Resource][Action]`   naming pattern.
-   API responses always include   `{ data, error, meta }`   structure — never raw data.


## Debugging Insights
-   If   `pnpm dev`   crashes with "Cannot find module './clerk-env'", run   `pnpm postinstall`   first.
```


Auto memory loads the first **200 lines or 25KB** of MEMORY.md per session. Content past that threshold is not loaded at startup. Keep it focused — auto memory is a curated knowledge base, not a session log.


**Viewing and editing:**


Run` /memory` inside any session. This opens all memory files for the current project. You can read, add, or remove entries directly. Toggle auto memory in that same view, or set` CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` in your environment to disable it globally.

## Layer 3: Path-Specific Rules


When CLAUDE.md starts growing past 150 lines, stop adding to it. Move specialized rules into` .claude/rules/` instead.


Each file in that directory can include YAML frontmatter with a` paths:` field that limits when the rules apply:


```text
---
paths:
-   "src/app/api/**"
---
# API Route Rules
-   Keep route handlers under 50 lines
-   Every route must use   `getVerifiedUser()`   for auth
-   Never expose internal error messages in responses
```


These rules load only when Claude reads files matching those paths — not at session start. Startup context stays lean. Specialized rules appear when Claude is actually working in that part of the codebase.


You can also import files directly inside CLAUDE.md using` @path/to/file` syntax. This lets you split a large file while keeping a single entry point.


## The Three-File Setup


For a solo developer starting fresh:


**` ~/.claude/CLAUDE.md`** — personal preferences across all projects. Your editor settings, formatting style, tools you always reach for.


**` ./CLAUDE.md`** (committed to version control) — project-specific stack, conventions, and hard stops. Run` /init` to generate a starting point, then edit.


**Auto memory** — let Claude build this over time. Run` /memory` once a week to review what it has saved and prune anything outdated or wrong.


> "The goal isn't to make Claude Code remember. It's to make remembering unnecessary. Encode intent so clearly that any session, starting fresh, can work effectively." — Dami Gupta, Towards AI, Feb 2026


For teams, add` ./CLAUDE.local.md` (gitignored) for personal project notes you do not want on the repo.


## Five Things to Add to CLAUDE.md Today


These five lines make an immediate difference in any project:


1. **Your package manager.**` Always use pnpm, not npm.` One line stops the most common correction every session.
2. **Your test command.**` Run pnpm test:unit for unit tests, pnpm test:e2e for integration.` Claude stops guessing.
3. **Your auth library and version.** Claude frequently suggests migrating to whatever is newest. Telling it what you use and why stops the suggestions permanently.
4. **Files Claude should never modify.**` Never modify src/generated/ — these files are auto-overwritten.` One line, never argue about it again.
5. **Your branch naming convention.**` Create branches as feat/description or fix/description — never commit directly to main.`


## Troubleshooting


**Claude is not following my CLAUDE.md:**


Check the file size first — past 200 lines, adherence drops. Check for scope conflicts: if user and project CLAUDE.md contradict each other, the more specific scope wins. Make instructions direct. "Use pnpm" works better than "This project generally prefers pnpm when possible."


**My instructions disappear after` /compact` :**


Project-root CLAUDE.md survives compaction — it reloads at every session start, separate from conversation context. Subdirectory CLAUDE.md files reload the next time Claude reads files in those directories. Auto memory also survives compaction; it stores independently from the conversation context.


**CLAUDE.md is already 300 lines:**


Move sections to` .claude/rules/` with path-scoped frontmatter. Use` @path/to/file` imports inside CLAUDE.md to reference external files while keeping a single entry point. The 200-line target applies to what loads into the context window per session.
