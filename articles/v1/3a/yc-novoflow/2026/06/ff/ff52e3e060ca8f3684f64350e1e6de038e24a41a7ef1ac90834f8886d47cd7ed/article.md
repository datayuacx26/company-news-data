## Why Standard Platforms Cannot Reach Legacy EHRs


Standard patient engagement platforms are built around API connections to EHR scheduling data. This architecture works well for modern, cloud-based systems that expose scheduling APIs. For clinics using legacy on-premise systems, proprietary platforms, or EHRs accessed through Citrix or Remote Desktop Protocol, those API connections are either unavailable or inaccessible.


In Citrix environments specifically, the EHR runs on a remote server and delivers only a pixel stream to the user's device. There is no application code, DOM, or data structure accessible from the client side. Standard automation tools receive only a video feed with no actionable structure, making them entirely ineffective in these environments.


Novoflow's visual AI addresses this at the architectural level. By operating at the screen level rather than through backend connections, it functions in any environment a human user can access.


## How Novoflow Handles Waitlist Automation on Any EHR


Novoflow reads the EHR schedule visually, detecting cancellations as they appear in the interface. When a slot opens, the AI identifies suitable waitlisted patients from the information visible in the system, contacts them using its AI voice agent, and books the replacement appointment directly within the EHR interface, the same way a human receptionist would.


The entire workflow from cancellation detection to rebooking happens automatically, without staff involvement. Because Novoflow operates at the screen level, it works on any EHR a human can log into, including 1990s-era systems, proprietary platforms, and those hosted in Citrix environments.
