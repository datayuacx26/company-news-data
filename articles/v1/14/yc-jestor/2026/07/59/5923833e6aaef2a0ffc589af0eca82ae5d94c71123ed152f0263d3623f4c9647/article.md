# What's the Access Difference Between a Member-Type User and a Builder-Type User?

In **Jestor** , a member-type user is meant for anyone who just uses already-configured processes, while a builder has access to create and edit tables, apps, automations, and the account's structure.


### Why separate these two access levels


Not everyone on the team should be able to change how a process works — the recommendation is that most people use what's already been set up, while only a few, usually the ones responsible for the structure, get builder access.


### What each type of user can do


- Member: fills out forms, moves cards, uses the day-to-day process
- Builder: creates and edits tables, apps, automations, and account settings
- The default recommendation is to keep most of the team as members
- Custom roles can further refine what each group can access


### How to set the access type when adding a user


1. Go to the users area inside Jestor's settings
2. Click add user and enter the person's email
3. Choose the seat type: usually member, with exceptions
4. Assign a specific role, if you need to further fine-tune permissions


### Process automation with control over who can change what


Separating member and builder is the foundation of permission control within **process automation** in Jestor, reducing the risk of someone accidentally changing a flow that other team members depend on.

## Frequently Asked Questions


**Which user type is recommended for most of the team?** The member type, reserving builder access for those who really need to change the structure of processes.


**Can a builder also use processes the way a member does?** Yes, the builder has broader access, including everything a member can already do.
