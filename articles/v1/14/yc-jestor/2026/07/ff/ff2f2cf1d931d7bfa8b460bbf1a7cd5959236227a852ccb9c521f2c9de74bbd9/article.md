# Why is an email confirmation code required before a bulk deletion?

In **Jestor** , deleting several apps, tables, or an entire folder at once requires a confirmation code sent by email before the deletion is finalized, as an extra layer of security against accidental mass deletions.


## How this security layer works


After selecting the items to be bulk deleted, Jestor lists everything about to be removed and, to confirm, sends a code to the registered email. Only after entering that code is the deletion actually carried out. Even so, deleted items go to a trash bin, from which they can be recovered if the deletion was done by mistake.


Security layer Function


**Email code** Confirms it was really the user who requested the deletion


**Trash bin** Lets you recover items deleted by mistake


## How to safely do a bulk deletion


1. Turn on builder mode.
2. Select the apps, tables, or folder you want to delete.
3. Review the list of items that will be deleted.
4. Enter the confirmation code sent by email to finalize the deletion.


## Why choose Jestor


- **Protection against mistakes** : the email code prevents accidental bulk deletions.
- **Recovery trash bin** : even after confirmation, the deletion can be reversed from the trash bin.
- **Faster cleanup** : accounts with lots of tests or AI-generated folders can be cleaned up in just a few clicks.


### Is the confirmation code sent for every deletion, even of a single item?


The confirmation code was introduced specifically for bulk deletions involving multiple apps, tables, or entire folders.


### Can you recover an item after the deletion has already been confirmed with the code?


Yes, deleted items go to the trash bin, from which they can be recovered afterward.


### Is this feature useful for people using AI to build apps?


Yes, it's especially useful for anyone using AI to create apps, since that process can generate several folders and templates that later need to be cleaned up quickly.
