# Why does a removed user show as inactive instead of being deleted, and what does that preserve in the history?

In **Jestor** , removing a user doesn't delete them from the system: their status changes to inactive, specifically to preserve the history of everything that person changed on records in the past.


## Why this logic exists


If a user were completely deleted, the entire history of actions they performed — such as changes to cards, approvals, and record updates — would lose its reference to who did what. By keeping the user as inactive, Jestor guarantees that any entry in the history correctly continues to show that person was responsible for a given change, even though they no longer have access to the account.


Status What it means


**Active** User with normal access to the account


**Inactive** Removed user, no access, but with history preserved


## How to check inactive users


1. Go to the user management area.
2. Use the status filter to view only inactive, active, or all users.
3. Confirm that inactive users are exactly the ones removed earlier.
4. Check the table's history to see actions performed by those users in the past.


## Why choose Jestor


- **Intact history** : no change loses its authorship reference, even after a user is removed.
- **Clear management filters** : you can quickly view just the active ones, just the inactive ones, or everyone.
- **Reorganized visuals** : the user management area also works in dark mode.


### Can an inactive user access the account again?


No. Inactive status means the user was removed and no longer has access; only their action history remains recorded.


### Can you see how many inactive users an account has?


Yes, the status filter lets you see exactly how many users are inactive, active, or any other status.


### Does an inactive user still occupy a seat in the account?


The user management area shows the count of available seats, which helps track account usage as users are removed or added.
