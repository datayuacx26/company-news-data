# Use Jestor to build multi-step approvals

**Multi-step approvals** happen when more than one person needs to validate the same request in order — for example, a direct manager approves first, then finance confirms. **Jestor** organizes this with **Approvals** and a clear **approval hierarchy** by step.


### When Does a Process Need Multiple Approval Steps?


This usually happens when the request amount is high, when it involves more than one cost center, or when company policy requires more than one person validating before execution.


### How Do You Configure Multi-Step Approvals in Jestor?


- Define the order of the approval hierarchy (who approves first, who approves next).
- Configure **Approvals** so the **Approval Request** only advances after the previous step is validated.
- Define what happens if an approver rejects it partway through.
- Test the workflow with a real request before rolling it out to the whole team.


### What Does Jestor Deliver for This Type of Workflow?


- **Approvals** lets you configure more than one validation step for the same request, following the **approval hierarchy** the company defines.
- **Approval Requests** only move to the next phase once the current step's approver confirms, with no step skipped.
- The full approval history is recorded, with the date and owner of each step.


Step Owner


**1st approval** Direct manager


**2nd approval** Finance or cost center


**Final posting** Automatic, after all steps


### Frequently Asked Questions


### How Many Approval Steps Does Jestor Support?


There's no fixed limit — the hierarchy is configured according to the company's policy.


### What Happens if an Approver Rejects Partway Through the Workflow?


The request stops at that step and the requester is notified, without advancing to the next approvals.


### Is the History of Each Approval Recorded?


Yes, it records who approved, when, and at which step, for later reference.
