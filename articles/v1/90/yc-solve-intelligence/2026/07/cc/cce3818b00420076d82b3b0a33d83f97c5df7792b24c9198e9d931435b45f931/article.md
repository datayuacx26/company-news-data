# Solve Intelligence × iManage: Solve’s Patent Workflows and AI agents seamlessly integrated with your Firm’s Intelligence

### **Unlock Your Firm's IP Knowledge**


Until now, getting documents from iManage into Solve meant downloading files, re-uploading them, and manually assembling context. Beyond the time cost, that process can also carry real governance risk, i.e., duplicating sensitive client materials outside your firm's controlled environment and creating version confusion that compounds as a matter develops.


With the Solve × iManage integration, that friction is gone. Attorneys can browse and import documents directly from their iManage matters, including technical disclosures, prior prosecution history, client specifications, drawings, prior art, through an embedded interface inside Solve. No manual downloads. No re-uploads.


The integration works in both directions. When a draft is complete, it can be saved back to iManage: attorneys select the destination matter folder, the same as any manual save. The draft lands exactly where it belongs, without re-uploading from a local machine.


A patent attorney beginning a new application can pull the client's invention disclosure, related prior filings, and relevant prosecution history from iManage into Solve in seconds. From there, Solve reads and processes those files to inform drafting, the same way it works with any document loaded into a project. The resulting application draws on the materials the attorney has pulled in. Once complete, it can be saved back to iManage.


### **Built for How IP Practices Work**


We designed this integration around how patent practices actually operate, which means iManage stays the system of record. Solve connects to it; it doesn't replace it. Attorneys don't need to change their file management habits, learn a new workflow, or ask IT to reconfigure anything. The tools they rely on work together, and the drafting and overall work product gets better.


The connection uses OAuth 2.0: no third-party middleware. Users authenticate to iManage through Solve's interface, and firms will need to configure the Solve integration in their iManage instance (a one-time IT setup step). The connection is designed to respect iManage's existing access controls at the point of retrieval, so only documents the attorney is authorised to access should be retrievable through Solve (ethical wall enforcement is subject to confirmation through testing). Once documents are loaded into a Solve project, they remain available there until the attorney disconnects the integration or refreshes their project; access revocation in iManage is not automatically reflected in Solve. Within Solve's environment, Solve's own security and data handling policies apply. For firms handling the most sensitive IP in the world, security isn't a feature. It's a baseline. The integration is built to meet it.
